Apple 平台以一个 SwiftPM 包发布：每个版本的 Release 附件 `migo-<版本>-apple-sdk.zip`，
解压得到 `MigoApple/`。包里有两个产品，各对应一种平台，公开接口相同：安装游戏包，
再把它载入一个 `MigoGameView`。

| App | 产品 | `import` | 最低系统 | 内容 JavaScript 运行在 | 渲染 |
| --- | --- | --- | --- | --- | --- |
| iOS | `MigoApplePerformancePlus` | `import MigoApplePerformancePlus` | iOS 15.2 | WebKit 的 WebContent 进程（JavaScriptCore，带 JIT），Dedicated Worker 内 | 本 App 进程：Skia + ANGLE/Metal |
| macOS | `MigoMacV8` | `import MigoMacV8` | macOS 11 | 本进程：V8，带 JIT 与 WebAssembly | 本进程：Skia + ANGLE/Metal |

## iOS 为什么是 Performance+

iOS 不允许第三方进程开 JIT，但系统拉起的 WebKit WebContent 进程有 JIT 权限——边界划在
进程上，不在引擎上。Performance+ 因此让游戏的 JavaScript 在 WebContent 里跑（与
WKWebView 同一个 JavaScriptCore），渲染留在 App 进程：每帧的绘制命令跨一次进程边界，
由 Migo 的渲染器画进宿主的 `CAMetalLayer`。

这意味着 iOS 上**内容 JavaScript 的执行速度与 WKWebView 相同**，不存在“JS 更快”；两者的
差别在把画面送上屏的那条链路。0.9.7 时这条链路的对照性能数据尚未发布，不作性能声明。

另外有一条 `MigoAppleWebKit`（整页 WebKit、无 native 渲染）车道，它只有 WebView 会话，
**不在 SDK 里**：在 web 平台上实现 `migo.*` 之前，它没有可供内容调用的东西。

## 1. 获取 SDK

从 [SDK 下载页](https://minigame-labs.com/download.html) 或
[GitHub Releases](https://github.com/minigame-labs/migo-runtime/releases) 下载
`migo-<版本>-apple-sdk.zip` 与同名的 `.attestation.json`，先按
[下载校验](/docs/0.9/release/download-verification/) 核对再使用。解压后在 Xcode 中
*File → Add Package Dependencies → Add Local*，选中 `MigoApple/`，给 App target 链接
上表中对应平台的**一个**产品。

## 2. 安装并运行游戏

游戏包是一个根目录下有 `game.js` 的目录，随 App 打包。两个平台的调用完全相同：

```swift
// .unsigned：包在你自己（已签名）的 App 包内。
// .verified(publicKey:)：从网络下载的包，见下文「内容签名」。
let configuration = try MigoGameView.Configuration.standard(contentSigning: .unsigned)
try MigoGameInstaller.install(
    package: Bundle.main.url(forResource: "my-game", withExtension: nil)!,
    id: "my-game", version: appBuildNumber, into: configuration.directories)

let gameView = MigoGameView(configuration: configuration)
gameView.onEvent = { event in
    // .ready / .exitRequested / .failed / .error / .gameLog；iOS 另有 .restarted / .console
}
view.addSubview(gameView)          // 任意尺寸；首次布局时游戏拿到这个尺寸
gameView.loadGame(id: "my-game")   // 入口默认 game.js
```

`version` 让重复启动零成本：同一版本不会再拷一遍。游戏请求退出
（`migo.exitMiniProgram()`）时收到 `.exitRequested`，之后显示什么由 App 决定；同一个
view 可以接着载入下一个游戏。

`MigoGameView` 负责其余一切：引擎会话、`CAMetalLayer`、显示时钟、触摸（macOS 上还有
鼠标、滚轮和键盘）、App 生命周期、软键盘；在 iOS 上还负责音频会话，以及 WebContent
进程崩溃后的恢复（游戏从入口重启，事件为 `.restarted`，磁盘上的存档保留）。

完整可运行的 iOS 与 macOS App（解析这个附件并校验其 attestation）在
[migo-examples 的 `apple-swift/`](https://github.com/minigame-labs/migo-examples/tree/master/apple-swift)。
每个类型、字段与事件的逐项说明见 [Apple SDK 参考](/docs/0.9/apple-sdk/game-view/)。

## 3. 内容签名

`contentSigning` 没有默认值，必须显式选择：

- `.unsigned`：只用于随 App 一起签名分发的包。
- `.verified(publicKey:)`：32 字节原始 Ed25519 公钥。每个包都必须带 `manifest.json`
  （`{"version": 1, "entry": "game.js", "timestamp": <unix 秒>, "files": {"<路径>": "<sha256 hex>", ...}}`）
  与 `manifest.sig`（对 `manifest.json` 原始字节的 64 字节签名）。引擎在首次启动时完整
  校验，不匹配即拒绝。

启用签名校验时，引擎拒绝动态下载的分包（下载的分包不带签名）；包内自带的分包正常可用。

## 4. 平台注意事项

### iOS

- 游戏尺寸在启动时确定（小游戏只布局一次），请把承载的 view controller 锁定在游戏的
  方向上。
- `MigoGameView.unavailabilityReason` 说明当前设备能否运行这条车道（例如系统低于
  15.2），在展示入口前检查。

### macOS

- 用 hardened runtime 签名，并加 `com.apple.security.cs.allow-jit`。缺少时 view 拒绝
  启动并在 `onEvent` 里说明原因（V8 会在第一次编译时崩溃，而 jitless 的 V8 没有
  WebAssembly）。
- 签名前用 Run Script 构建阶段嵌入 ANGLE，并在 Runpath Search Paths 中加入
  `@executable_path/../Frameworks`：

  ```bash
  bash "$MIGO_PACKAGE/Frameworks/Scripts/embed-apple-angle.sh" \
    --frameworks-dir "$MIGO_PACKAGE/Frameworks" \
    --destination "$TARGET_BUILD_DIR/$FRAMEWORKS_FOLDER_PATH" \
    --architectures "$ARCHS" \
    --sign "$EXPANDED_CODE_SIGN_IDENTITY"
  ```

- 双显卡的 Mac 上，`MigoGameView` 让引擎在驱动窗口所在显示器的那块 GPU 上渲染。
  通过 C ABI 自己挂 `CAMetalLayer` 的宿主，要在 attach 之前把 layer 的 `device` 设为
  `CGDirectDisplayCopyCurrentMetalDevice`（窗口所在的显示器）；引擎在会话第一次 attach 时
  读取它。不设时引擎用系统默认 GPU，也就是独显，系统固定在核显上时窗口是黑的。

- `Configuration.mouse` 选择鼠标如何送给内容：`.touch`（面向手机的内容，默认）、
  `.pointer`（面向 PC 的内容）、`.touchAndPointer`（仅用于确知只监听其中一种的内容）。

## 5. 设备能力

`MigoGameView` 也回答内容对设备的询问：

| 接口 | iOS | macOS |
| --- | --- | --- |
| `setKeepScreenOn` | 空闲计时器；游戏结束时交还 App 原设置 | 电源断言；同左 |
| `getNetworkType` / `onNetworkStatusChange` | `NWPathMonitor`（有线记为 `wifi`，蜂窝记为 `unknown`，与 Android 一致） | 同左 |
| `vibrateShort` / `vibrateLong` | Taptic Engine | 回答“不支持” |
| `getBatteryInfo` | 电量与低电量模式 | 回答“不支持” |
| `getGameLogManager().log` | 以 `onEvent(.gameLog(json))` 交给 App | 同左 |

以下接口在这两条车道上**明确拒绝，不伪造结果**：`setDeviceOrientation`（尺寸在启动时
固定）、`setEnableDebug`（没有调试面板）、iOS 上的 `getHeapStatistics`（内容运行在
WebKit 的 JavaScriptCore 中，它不暴露堆数据），以及启用签名校验时的动态下载分包。

## 6. 验证记录

- **iOS 真机**：iPhone XS Max（iOS 18.7）上游戏安装、载入、按显示时钟出帧、退出回到
  App、同一 layer 上运行下一个游戏；软键盘；签名包的校验、更新与篡改拒绝；游戏的打包
  音效经宿主音频播放。
- **iOS 模拟器**（每个 PR）：真实的 WebContent 生产端对真实渲染器的验收套件，覆盖
  WebGL 与 2D、纹理、文字、图片、触摸、超过单包的帧、同步回读与音频。
- **macOS**（每个 PR）：`MigoGameView` 在 hardened runtime + allow-jit 签名的 App 中
  运行游戏：V8 JIT 与 WebAssembly、ANGLE 上的 Canvas2D、签名内容校验与篡改拒绝，以及
  缺少 entitlement 时拒绝启动。
- **发布**：只有在 `migo-<版本>-apple-sdk.zip` 本身被解压、为 iOS 与 macOS 构建并跑通一个
  游戏之后才会发布（`scripts/test-apple-sdk-release-asset.sh`）。

## 从源码构建

需要 macOS 与 Xcode。先安装钉住的 ANGLE（构建脚本从不自行下载），再构建各平台组：

```bash
bash scripts/fetch-apple-angle.sh ios
bash scripts/fetch-apple-angle.sh ios-simulator
export MIGO_APPLE_BUILD_ROOT=/tmp/migo-apple-build
bash scripts/build-apple-sdk.sh --platform ios --configuration Release
bash scripts/build-apple-sdk.sh --platform ios-simulator --configuration Release
```

macOS V8 组、ANGLE 的源码构建与嵌入细节见
[`platforms/apple/README.md`](https://github.com/minigame-labs/migo-runtime/blob/HEAD/platforms/apple/README.md)。
