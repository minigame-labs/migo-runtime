Linux 以可链接的 C ABI SDK 发布：每个版本的 Release 附件 `migo-<版本>-capi-linux-x86_64.tar.gz`
与 `migo-<版本>-capi-linux-arm64.tar.gz`（`libmigo.so`、`libmigo.a`、头文件、pkg-config 与 CMake
包，仅 glibc）。`platforms/linux/host-kit/` 是其上的源码级适配器，用于把 Migo 嵌进应用自己的
Linux UI；它不创建应用、顶层窗口或事件循环——这些始终归宿主。

本文驱动宿主创建的最小 C ABI 管线，验证 surface 挂载和生命周期。

当前已声明的三个 CMake 目标：

- `migo::linux-surface-host` — 工具包中立的 C++17 生命周期控制器，接受宿主提供的 X11
  或 Wayland 句柄。
- `migo::qt6-x11-surface-view` — 基于 `xcb` 平台插件的 Qt 6.4+ Widgets 适配器，使用
  原生子 `QWidget`，负责 surface 生命周期、输入、焦点、IME 合成和帧请求。
- `migo::qt6-host-services` — 宿主服务通道的 Qt 实现，以及 Qt 自带能力回答的内建服务
  （剪贴板、toast/loading/modal/action sheet、窗口的尺寸/状态/光标、屏幕、图片与文件的压缩/选取/保存）。
- `migo::qt6-managed-session` — Managed 所有权形态：`MigoManagedSession` 拥有 Session、
  回调表和 view，并装上内建服务。

Qt Wayland、Qt Quick 和 GTK 4 **尚不支持**。公开 C ABI 仍标记为
`MIGO_C_ABI_CANDIDATE`；在 ABI 冻结之前，此 Host Kit 为集成预览版本。

## 1. 准备环境

在 Ubuntu 24.04 上安装 Qt Widgets/X11 适配器及其合约测试所需的全部依赖：

```bash
sudo apt-get update
sudo apt-get install -y \
  cmake ninja-build g++ ripgrep xvfb xauth \
  qt6-base-dev qt6-base-dev-tools qt6-qpa-plugins \
  libx11-dev libxkbcommon-x11-dev libxcb-cursor0 \
  pkg-config libxcb-xinput-dev libxtst-dev libudev-dev dbus
```

若宿主只使用工具包中立的 `migo::linux-surface-host` 控制器（Wayland），还需：

```bash
sudo apt-get install -y libwayland-dev
```

不要安装 Qt 私有头文件包；Host Kit 不依赖任何私有 Qt API。

运行时，`createVideoDecoder` 经 GStreamer 解码：引擎在系统有 GStreamer 时加载它，不链接它。需要其基础插件（`playbin`、`videoconvert`）以及视频所需的解复用器与解码器——MP4 需要 `gstreamer1.0-plugins-good`，H.264 等需要 `gstreamer1.0-libav`。没有 GStreamer 的系统照常运行所有游戏，只有 `createVideoDecoder` 回答不支持。

```bash
sudo apt-get install -y gstreamer1.0-plugins-base gstreamer1.0-plugins-good gstreamer1.0-libav
```

## 2. 获取 Linux SDK

Host Kit 依赖 Linux SDK（提供 `find_package(migo)` 所需的 CMake 包）。从
[SDK 下载页](https://minigame-labs.com/download.html) 或
[GitHub Releases](https://github.com/minigame-labs/migo-runtime/releases) 下载
`migo-<版本>-capi-linux-x86_64.tar.gz` 与同名的 `.attestation.json`，按
[下载校验](/docs/release/download-verification/) 核对后解压，得到 `migo-linux-x86_64/`。
其中 `share/migo/linux-x86_64-manifest.json` 记录 glibc 下限与全部动态依赖。

从源码构建见 [`BUILD.md`](https://github.com/minigame-labs/migo-runtime/blob/HEAD/BUILD.md)
"4. Linux x86\_64 SDK" 一节：

```bash
bash scripts/fetch-linux-sysroot.sh
bash scripts/fetch-v8-archives.sh x86_64-linux-gnu
bash scripts/build-linux-sdk.sh
bash scripts/test-linux-sdk-contract.sh
```

SDK 构建完成后位于 `dist/migo-linux-x86_64/`。

## 3. 将 host-kit 加入应用构建

将 SDK 目录传给 `CMAKE_PREFIX_PATH` 后，作为子目录嵌入：

```cmake
find_package(migo CONFIG REQUIRED)
add_subdirectory(path/to/migo/platforms/linux/host-kit migo-host-kit)

target_link_libraries(my_app PRIVATE migo::qt6-x11-surface-view)
```

只需 `migo::linux-surface-host`（不引入 Qt）时，链接该目标即可：

```cmake
target_link_libraries(my_app PRIVATE migo::linux-surface-host)
```

Host Kit 也可单独构建并安装：

```bash
cmake -S platforms/linux/host-kit -B build/host-kit \
  -DCMAKE_PREFIX_PATH=/path/to/migo-sdk \
  -DCMAKE_INSTALL_PREFIX=/path/to/prefix \
  -DMIGO_LINUX_HOST_KIT_ENABLE_INSTALL=ON
cmake --build build/host-kit
cmake --install build/host-kit
```

安装后消费者使用：

```cmake
find_package(migo-linux-host-kit CONFIG REQUIRED)
target_link_libraries(my_app PRIVATE migo::qt6-x11-surface-view)
```

## 4. 最小集成

应用创建 Session 后，构建一个包含 `SurfaceHost` 和 `MigoQtX11SurfaceView` 的 `QWidget`：

```cpp
class GamePane final : public QWidget {
public:
    GamePane(MigoSession *session, QWidget &parent)
        : QWidget(&parent),
          surface_host_(session),
          game_view_(surface_host_, *this) {
        layout_.addWidget(&game_view_);
        setLayout(&layout_);
    }

private:
    QVBoxLayout layout_;
    migo::linux_host::SurfaceHost surface_host_;
    migo::linux_host::qt6::MigoQtX11SurfaceView game_view_;
};
```

应用（而非封装类）持有 `MigoSession`、`SurfaceHost`、父 widget 和原生窗口。
必须保证两条依赖链同时有效：

```text
QApplication > parent QWidget > MigoQtX11SurfaceView
MigoSession  > SurfaceHost ──> MigoQtX11SurfaceView
```

`QApplication` 必须在 Qt view 之前存在并在其最终 release 之后才销毁，因为 Qt
拥有 X11 连接和 GUI 事件循环。

### 宿主服务

内容调用 `migo.showToast`、`showModal`、`setClipboardData` 这类 API 时，引擎经 C ABI 的
宿主服务通道请宿主回答（`MigoHostCallbacks.host_services` 与 `on_host_service_call`）。
`migo::qt6-host-services` 的 `MigoQtBuiltInHostServices` 用 Qt 自带的能力回答其中桌面已经提供的部分：

- **剪贴板**（`setClipboardData`、`getClipboardData`）：`QClipboard`。
- **交互**（`showToast`、`hideToast`、`showLoading`、`hideLoading`、`showModal`、`showActionSheet`）：
  toast 与 loading 是叠在游戏上方、不接收输入（点在上面就是点游戏）的指示窗，同一时间只显示一个，`hideToast` 只收 toast、
  `hideLoading` 只收 loading，带 `mask` 时游戏收不到玩家输入；modal 是窗口模态对话框，
  `editable` 时 `content` 是输入框的初始文字；action sheet 是游戏中央弹出的菜单，关闭菜单即以
  `cancel` 失败。按钮颜色不应用：桌面的对话框是桌面的。
- **窗口**（`setWindowSize`、`setCursor`、`requestPointerLock`、`onWindowStateChange`）：`setWindowSize` 是游戏的像素尺寸，窗口按视图需要的差额伸缩（全屏时拒绝）；窗口状态变化（最小化、最大化——全屏也算——、复原）逐次上报；`setCursor` 设置游戏上方的光标，CSS 关键字或图片加热点。指针锁只在玩家在游戏上时授予——视图持有键盘焦点、光标在视图可见部分之上，否则拒绝并上报：锁定期间光标隐藏、鼠标被抓取，XInput 2 的原始位移（经过指针加速）从光标原处移动内容的指针，可越过视图边缘，点击落在内容的指针处；Esc 释放（这次 Esc 及其抬起不交给游戏），视图失去焦点、游戏结束也释放，释放后光标回到原处。
- **屏幕**（`setDeviceOrientation`、`onDeviceOrientationChange`、`setEnableDebug`）：桌面的屏幕不会转，转的是窗口，所以屏幕方向就是游戏的形状——视图高大于宽为 portrait，否则 landscape，视图每次从一种形状跨到另一种时上报一次；`setDeviceOrientation` 把窗口转成所要的形状（视图宽高互换；全屏时、屏幕放不下转后的窗口时拒绝）。`setEnableDebug` 打开或关闭调试辅助：`MigoManagedSession` 在游戏上方 40% 处显示一个面板——每秒帧数和此后内容写到控制台的内容——不接收任何输入，游戏照常可玩，并把 `MIGO_HOST_APP_INFO_FLAG_DEBUG` 报给 Session（`getAppBaseInfo().enableDebug`）；自己回答屏幕服务的 App 用 `setDebugAids()` 开关。屏幕亮度（`getScreenBrightness`、`setScreenBrightness`）是背光的：从内核在 `/sys/class/backlight` 给出的背光读取（固件的优先于平台的、再优先于 raw，与 systemd、GNOME 的选法一致），经 logind 的 `Session.SetBrightness` 设置（活动会话的用户无需特权），0 是最暗而不是熄灭；没有背光的屏幕（外接显示器、虚拟机）拒绝。截屏、录屏通知与 `setVisualEffectOnCapture` 不提供：Linux 桌面不告诉应用有人截屏或录屏，也无法把窗口排除在截屏之外（X11 上任何客户端都能读任何窗口）。
- **图片**（`compressImage`、`chooseImage`、`chooseMedia`、`chooseMessageFile`、`saveFileToDisk`、`saveImageToPhotosAlbum`、`previewImage`、`previewMedia`）：`compressImage` 用 Qt 的图片读取器读取——按 EXIF 方向摆正，格式允许时（如 JPEG）直接按所要尺寸解码——PNG 仍写成 PNG，其余写成所要质量的 JPEG（最多 5000 万像素，与其他平台一致）。选取器是文件对话框——Qt 找得到时用桌面自己的（经门户或平台主题），否则用 Qt 自带的——游戏拿到的是副本，绝不是玩家的原文件：JPEG、PNG、GIF、BMP、WebP 原样复制，Qt 能读的其他格式（TIFF、SVG、有插件时的 HEIF）摆正后有透明写 PNG、无透明写 JPEG。`chooseMessageFile` 给每个文件附上玩家看到的文件名、类别（`image`、`video` 或 `file`，按桌面认定的类型）和最后修改时间；`extension` 按参考文档只对 `type: 'file'` 生效。对话框不计数，取玩家所选的前 `count` 个。`saveFileToDisk` 是保存对话框，复制完整后才替换已有文件；`saveImageToPhotosAlbum` 写进玩家的图片目录（XDG `PICTURES` 目录），命名为 `IMG_<毫秒>.<后缀>`，不是图片则拒绝。交给游戏的文件先暂存在 App 的缓存目录（`QStandardPaths::CacheLocation`），调用完成时由引擎取走——引擎的 `cache_dir` 在同一卷上时只是一次重命名——没被取走的会删除。同一时间只显示一个文件对话框。预览是游戏上方、与其窗口同大的查看器：一次一张、按查看器大小适配，从内容指定的那张开始；左右方向键或两侧按钮切换，Esc 或关闭按钮关闭，无法解码的图片显示警告图标。答复之前每张图片都已打开并持有，所以引擎可以在答复后收回它借出的文件；http(s) 图片（引擎已按会话网络策略放行，与内容自己下载同一规则）经 Qt 网络下载，不带 referrer，写入一个创建即删除的临时文件。新的预览替换正在显示的那个。视频由可选组件 `migo::qt6-media` 提供（见下）：没有它时 `chooseMedia`、`previewMedia` 拒绝视频。相机拒绝。
- **视频**（`chooseMedia`、`previewMedia`，需 `migo::qt6-media`）：由 GStreamer 描述和播放——Linux 上引擎的解码器也用它。它是单独的组件，因为它链接 GStreamer，而 Host Kit 其余部分不链接：配置 Host Kit 时加 `-DMIGO_LINUX_HOST_KIT_BUILD_QT6_MEDIA=ON`（需要 `libgstreamer1.0-dev` 与 `libgstreamer-plugins-base1.0-dev`），链接 `migo::qt6-media`，并把一个 `MigoQtMedia` 交给会话：

  ```cpp
  MigoManagedSession::Options options;
  options.videos = std::make_shared<MigoQtMedia>();
  ```

  此后 `chooseMedia` 提供图片和视频（或按 `mediaType` 只提供视频），并像其他平台一样描述视频：`duration` 为秒，`width`、`height` 为显示时的尺寸（转着录的视频按摆正后量，非方形像素按应有的形状），首帧作封面（`thumbTempFilePath`，JPEG）；GStreamer 读不了的视频答以零值且无封面。`previewMedia` 在查看器里播放视频（带声音）：首次播放前显示 `poster`（没有则显示首帧），点击画面或按钮播放、暂停，进度条拖动定位。文件经查看器持有的句柄播放，所以引擎可以收回它借出的文件；http(s) 视频边下边播。能播放哪些视频取决于 GStreamer 插件：MP4、WebM 需要 `gstreamer1.0-plugins-good`，H.264 等大多数编码需要 `gstreamer1.0-libav`。
- **定位**（`getLocation`、`getFuzzyLocation`）：GeoClue 给出的位置——沙箱外经系统总线问 GeoClue，沙箱内（Flatpak、Snap）经 XDG 桌面门户的 `Location` 问，由门户替 App 问 GeoClue。`getLocation` 按街道级精度请求，`isHighAccuracy` 时按精确级；等待 10 秒（同时给了 `highAccuracyExpireTime` 则按它），拿不到位置失败为 `unable to get location`；`getFuzzyLocation` 按城市级请求，引擎再对结果取整。GeoClue 运行期间的请求共享这一次运行，全部答复后即停止。GeoClue 用 `QGuiApplication::desktopFileName()`（没有则用应用名）向其 agent 标识 App：请设为 App 的 desktop 文件 id。
- **蓝牙**（`openBluetoothAdapter` 及 BLE 主机端 API）：系统总线上的 BlueZ——适配器（未开启报 `10001`）、按所给服务过滤的 BLE 扫描（`SetDiscoveryFilter`）、听到即上报的设备（按 `interval` 批量，除非 `allowDuplicatesKey` 否则每个只报一次）、提供某服务的已连接设备，以及在 BlueZ 解析完设备服务后才答复的连接（遵守 `timeout`，已连接的报 `-1`）。服务、特征、读（值单独送达）、有/无应答的写、通知、MTU（BlueZ 5.62 起）与其他平台一致，错误码用通用小游戏平台的。设备以地址标识。按服务扫描时只上报提供其一的设备，无论还有谁在扫描。已连接设备的 RSSI（BlueZ 不向应用提供）、配对与设置 MTU（参考文档写明仅 Android）、外围设备模式均拒绝。只在适配器打开期间镜像 BlueZ 的对象。
- **iBeacon**（`startBeaconDiscovery`、`getBeacons`、`onBeaconUpdate`、`onBeaconServiceChange`）：从 BlueZ 报告的 BLE 广播里听——类型 2、长度 21 的 Apple 段——用独立的扫描（自己的 D-Bus 连接，内容的设备扫描与信标扫描互不收窄、互不停止），只认所请求的 proximity UUID（128 位，否则 `11006`）。每秒上报一次范围内的信标（与 CoreLocation 测距一致），10 秒没听到的移除；距离与远近按 Android SDK 的公式由 RSSI 与发射功率估算。蓝牙关闭报 `11001`。再次开始即改测新的 UUID。
- **运动传感器**（`startAccelerometer`、`startGyroscope`、`startCompass`、`startDeviceMotionListening` 及对应的停止）：内核经 IIO 给出的加速度计、陀螺仪、磁力计，经 udev 找到，换算到屏幕坐标系（x 向右、y 沿屏幕向上、z 指出屏幕）——优先用 udev 的 `ACCEL_MOUNT_MATRIX`（硬件数据库对该机型的校正），否则用内核的 `mount_matrix`；二合一设备取屏幕一侧的加速度计而非底座的。按请求的间隔（`game` 20 毫秒、`ui` 60 毫秒、`normal` 200 毫秒）在独立线程读取。罗盘航向与设备方向由重力和磁场按 Android `SensorManager` 的同一算法求出，两个平台对同一姿态给出相同结果；IIO 不提供磁力计的校准信息，罗盘精度报 `unknown`。设备没有的传感器以缺什么为原因拒绝，不编造数据。Host Kit 因此链接 libudev。
- **权限**（`authorize` 及需要 scope 的调用）：桌面能决定的 scope。`scope.userLocation`（以及 `scope.userLocationBackground`——桌面没有另一种）由 GeoClue 决定——App 第一次请求时由其 agent（沙箱内由门户）询问玩家——并记录为已决定；没有 GeoClue 就无人可问，scope 保持未决定。`scope.writePhotosAlbum` 直接授予：玩家的图片目录属于玩家与 App，桌面不对它设关卡。其他 scope 一律拒绝（`auth deny`）：要自己决定 scope 的 App（登录、自己的授权弹窗）整个回答权限服务。

`MigoManagedSession` 读取内核给出的手柄（`getGamepads`、`onGamepadConnected`、`onGamepadDisconnected`、`vibrationActuator`）：udev 标为摇杆的 evdev 设备，随插随拔。遵循内核手柄布局（`Documentation/input/gamepad.rst`）的手柄映射到 W3C 标准布局——17 个按键、4 个轴，模拟扳机与十字键的 hat 按驱动报告的位置取——不遵循的原样传递（按键与轴按编码顺序，`mapping` 为空）。驱动支持 `FF_RUMBLE` 且可写打开的手柄有双马达震动。采样时间戳用 `CLOCK_MONOTONIC`，与 X 服务器给视图输入盖的时钟一致。读取手柄需要能访问其 `/dev/input/event*` 节点：桌面会话会授予登录用户（udev 的 `uaccess`），Flatpak 内需要 `--device=all`。

`MigoManagedSession` 还替内容保持屏幕常亮（`setKeepScreenOn`）：经 XDG 桌面门户的 `Inhibit`（会话空闲：熄屏、锁屏）向桌面申请，桌面没有门户时退回 freedesktop 屏保接口（`org.freedesktop.ScreenSaver.Inhibit`）；内容不再要求或游戏结束时释放。两者都没有的桌面不做任何保持，并记一条警告。

它也把系统给出的电量和网络报给 Session，并在变化时再报：电量是 UPower 的显示设备（所有电池合成一个）的电量与是否充电，power-profiles-daemon 的省电档即低电量模式（`isLowPowerModeEnabled`）；没有电池的机器不报，内容的 `getBatteryInfo` 如实答"不支持"。网络是 NetworkManager 的主连接：Wi-Fi 与有线都报 `wifi`（API 里最接近的），调制解调器报 `unknown`（代数不归 NetworkManager 说），断开报 `none`；是否连通互联网看 NetworkManager 的连通性检查，检查关闭时看它的状态。没有 NetworkManager 的机器不报。Wi-Fi 开关（`getSystemSetting` 的 `wifiEnabled`）也取自 NetworkManager：软件开关与无线电的硬件开关都开着才算开。

内容随窗口运行与显示：窗口显示且未最小化时运行（`onShow`），最小化或隐藏时暂停（`onHide`）；窗口被完全遮挡（X 不再暴露它）时内容仍在运行，只是不可见——像浏览器后台标签页仍在运行脚本。游戏一启动就是显示且运行的，变化时才报。

`getAppAuthorizeSetting`：沙箱外的 Linux 应用没有系统层面的授权关卡——文件、设备、通知都是运行它的用户的——所以相册、蓝牙、摄像头、麦克风、通知、日历都报"已授权"；在沙箱里（Flatpak、Snap）由门户在内容使用时决定，报"未决定"。定位由 GeoClue 的代理决定，Host Kit 尚未询问，报"未决定"。

内存不足的警告（`onMemoryWarning`）在 GLib 听的地方听：沙箱外是系统总线上 low-memory-monitor 的 `LowMemoryWarning`，沙箱内是转发它的桌面门户的 `MemoryMonitor`。级别 50（低）、100（中）、255（危急）分别报为 Migo 的 moderate、low、critical，引擎先释放相应比例的缓存再通知内容。两者都不运行的桌面不发出任何警告。

`MigoManagedSession` 自动装上这些服务。App 自己回答的服务（广告、支付、登录……）用构造参数
`Options::appServices` 提供一个 `MigoQtHostServiceProvider`：App 声明的服务归 App，包括内建
也能回答的；其余由内建回答。同一个 `Options` 还带网络策略（`networkPolicyJson`，不给则游戏
没有任何网络）和启动参数（`launchOptionsJson`），两者都是 `MigoSessionConfig` 的同名 JSON；`appId` 是内容读到的 `getAppBaseInfo().host.appId`，不填则取 `QGuiApplication::desktopFileName()`（Linux App 给自己起的名字）：

```cpp
class AppServices final : public migo::linux_host::qt6::MigoQtHostServiceProvider {
public:
    std::uint64_t services() const noexcept override {
        return migo::linux_host::qt6::hostServiceBit(MIGO_HOST_SERVICE_AD);
    }
    void call(MigoHostService service, std::uint32_t method, const QJsonObject &request,
              migo::linux_host::qt6::MigoQtHostServiceReply reply) override {
        // 交给广告 SDK；结果到达时 reply.succeed(...) 或 reply.fail("...")，恰好一次。
    }
};

migo::linux_host::qt6::MigoManagedSession::Options options;
options.networkPolicyJson = R"({"request": ["api.example.com"]})";
options.appServices = &app_services;  // 须比 Session 活得久
migo::linux_host::qt6::MigoManagedSession game(engine, window, options);
```

自己持有 Session 的 App（Bound 形态）直接用 `MigoQtBuiltInHostServices` 与
`MigoQtHostServiceChannel`：在自己的 `on_host_service_call` 里把调用交给它，并在
`migo_session_destroy` 之前关闭通道。对话框可能在游戏结束后才被回答，关闭的通道让这样的
回答不再到达已销毁的 Session。

## 5. 输入与帧

- **坐标为 CSS 像素，无需转换**：Qt 的逻辑位置 = 物理像素 ÷ device pixel ratio，
  与 view 报告的 `scale_factor` 相同；在此处再乘以它会在 HiDPI 屏幕上把每次点击
  偏移到错误位置。
- **鼠标默认同时驱动两个事件流**：`setPointerDelivery()` 可将其缩窄。
- **`code` 来自硬件扫描码，`key` 来自布局**：WASD 移动对所有键盘布局均有效。
- **帧跟随 Qt 的时钟**：宿主在 `on_request_frame` 回调中调用 `requestFrame()`，
  view 触发 `QWindow::requestUpdate()`。

## 6. 关闭顺序

拆卸是 C ABI 的三个步骤，不能缩短：

1. 调用 `close()` 开始 detach，立即返回。
2. view 的 release observer 报告 `MIGO_SURFACE_RELEASE_RELEASED`。
3. 只有在此之后才能销毁 Session。

删除 view 或其任何拥有原生子窗口的祖先之前，必须先调用 `close()` 或
`beginDetach()`，然后保持 widget 和 GUI 事件循环有效，直到 `surfaceReleased`
信号触发。在 release 完成之前销毁窗口是 use-after-free；适配器会在此情况下
快速失败而非隐藏此错误。

## 7. 已知限制

- **Qt Wayland**：Qt 6.4 没有通过受支持的公开 API 暴露适配器所需的 Wayland
  display/surface 对；私有 Qt 头文件被明确禁止。
- **GTK 4**：GTK 4 移除了 `GtkSocket`/`GtkPlug`，没有公开方式将原生目标放入
  布局中。`scripts/test-gtk4-surface-capability.sh` 持续探测这一状态，用证据
  而非文档陈述该限制。
- **Qt Quick**：使用合成器拥有的场景图，子窗口覆盖层会破坏裁剪、变换和帧调度，
  暂不支持。
- **软键盘**：`MigoManagedSession` 明确拒绝软键盘能力；桌面宿主通过物理键盘传递输入，
  `migo.showKeyboard` 在此正确报告失败。
