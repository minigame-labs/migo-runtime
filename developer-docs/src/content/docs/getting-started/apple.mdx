本页记录 Apple 平台的**当前构建状态**，而非端到端集成步骤。
Apple README 原文：「Not a skeleton any more, and not a product either.」
区分两者的标准是编译器是否见过它——因此本节仅报告编译器见到了什么。

iPhone XS Max 上 `MigoGameView` 已运行游戏（iOS 18.7，2026-09-25），含帧时钟、软键盘与内容签名验证；macOS 上 V8+JIT 已在签名应用中运行游戏。设备性能（帧率、内存等具体数值）尚未测量，不作宣称。

## 当前构建状态

| 组件 | 状态 |
| --- | --- |
| `core/`（`MigoAppleCore`） | 在每次 PR 上于 Apple silicon runner 构建、测试并交叉编译为 `aarch64-apple-ios` |
| `Sources/MigoAppleRenderer` | Apple SDK workflow 构建 iOS/simulator shipping slices 及独立 macOS external-frame 诊断包；macOS 诊断包不是 V8 产品测试 |
| `Sources/MigoAppleWebKit` | 占位符；可编译，有 session 但无内容渲染面；未进入 SDK |
| `Sources/MigoApplePerformancePlus` | 验收套件在 iOS 模拟器上运行真实 WebContent producer 与真实渲染器：游戏通过引擎自有 WebGL/Canvas 渲染帧；`MigoGameView` 运行已安装游戏（无测试供给，游戏自行启动帧时钟并退出后可重启） |
| `Sources/MigoMacV8` | `MigoGameView` 在带硬化运行时与 allow-jit 签名的应用中运行游戏：V8+JIT+WebAssembly、Canvas2D on ANGLE、帧时钟、内容签名验证与拒绝 |
| `WebContent/PerformancePlus` | 编码器在每次 PR 上于 node 下对同一黄金语料库运行 |
| `ProbeApp/` | 源码存在；回答 G0 探测问题，不链接进任何产品 |
| iPhone XS Max（iOS 18.7） | `MigoGameView` 在真机上运行（2026-09-25）：游戏安装、帧时钟、退出后重启、软键盘、内容签名验证与音频播放 |

## 三条产品路线

| 产品 | 内容 JS 运行位置 | 渲染器 | 进入 v1 |
| --- | --- | --- | --- |
| `MigoAppleWebKit` | WebContent，完整 Web 平台 | WebKit | 是 |
| `MigoApplePerformancePlus` | WebContent，Dedicated Worker | 本进程：Skia + ANGLE/Metal | 是（iOS 15.2+） |
| `MigoMacV8` | 本进程，V8 with JIT | 本进程：Skia + ANGLE/Metal | 是（仅 macOS） |

`MigoAppleRenderer` 被 Performance+ 和 MacV8 两条 native 渲染 lane 共享；
`MigoAppleWebKit` 有意不依赖它——请求了兼容性基线的宿主不应链接一个永远不会驱动的渲染器。

## 两个 SwiftPM 包

仓库包含两个包，拆分是有意义的负载：

- **`platforms/apple/core/Package.swift`**（`MigoAppleCore`）：无引擎依赖，无需拉取
  或构建任何内容即可解析和构建。包含 profile policy、部署底线、生命周期、权限、metrics。
- **`platforms/apple/Package.swift`**（shipping package）：声明一个 binary target，
  指向 `scripts/build-apple-sdk.sh` 生成的 xcframework；在 Mac 上运行该脚本之前
  无法解析。shipping package 在 Mac 上运行 `build-apple-sdk.sh` 之前无法解析；SDK 制品构建完成后，完整 Swift 包含 session、显示时钟与签名验证可一并构建测试。`core/` 是不需要引擎的那半部分，因此在每次 PR 上独立构建和测试。

## C ABI Surface 类型

`include/migo/platform/ios.h` 声明两种 iOS surface 描述符：

- `MigoIosUiViewDescriptor`：持有宿主拥有的 `UIView*`（便捷路径；Host Kit 创建并
  拥有该 view 的唯一 `CAMetalLayer` backing）。
- `MigoIosMetalLayerDescriptor`：持有宿主拥有的 `CAMetalLayer*`（Performance+ lane
  需要宿主拥有的 Metal surface；这是权威路径）。

`include/migo/platform/macos.h` 声明两种 macOS surface 描述符：

- `MigoMacosNsViewDescriptor`：持有宿主拥有的 `NSView*`（注释标明为
  "A future implementation"）。
- `MigoMacosMetalLayerDescriptor`：持有宿主拥有的 `CAMetalLayer*`。macOS 上的
  `CAMetalLayer` 挂载已在 CI 上运行（apple-sdk.yml run 34017950809），完成了完整的
  retirement 握手：`begin_detach`、轮询至 `MIGO_SURFACE_RELEASE_RELEASED`、
  `migo_surface_release_destroy`、`migo_session_destroy`、`migo_engine_destroy`。

## 构建（需要 macOS + Xcode）

`core/` 无引擎依赖，可独立解析、构建和测试：

```bash
bash scripts/test-apple-swift-core-engine-free.sh
```

shipping package 需要先安装 ANGLE 并构建 SDK，**仅限 macOS**：

```bash
bash scripts/fetch-apple-angle.sh ios
bash scripts/fetch-apple-angle.sh ios-simulator
export MIGO_APPLE_BUILD_ROOT=/tmp/migo-apple-build
bash scripts/build-apple-sdk.sh --platform ios --configuration Release
bash scripts/build-apple-sdk.sh --platform ios-simulator --configuration Release
```

产出 `platforms/apple/Frameworks/MigoEngine.xcframework`，包含 iOS device 和
iOS simulator 两个 platform group。

macOS external-frame 渲染器/ABI 诊断测试（不是 V8 产品测试）：

```bash
bash scripts/build-apple-sdk.sh --platform macos \
  --product external-frames-diagnostic --configuration Debug
```

packaging 契约可在无 Xcode 的情况下验证：

```bash
bash scripts/test-apple-shipping-package-contract.sh
bash scripts/test-apple-sdk-packaging.sh
```

## 尚未完成的内容

以下内容**目前尚未完成**；不作宣称：

- `MigoAppleWebKit` 应用 session——此 lane 可编译但不运行游戏；它是 Lockdown Mode 设备与 App Review 首次提交的兼容性基线，待有客户需求后构建。
- **设备性能测量**——iPhone XS Max 上游戏已运行，但帧率、内存、CPU 等具体数值尚未测量，不做任何性能宣称。
- macOS App Store 完整签名与真机上架流程——macOS V8 本地构建与测试通过，但完整 App Store 路径的真机验证尚未完成。
