`GameSession` 持有 native 会话(`sessionId`)并负责与活动 / 视图桥接:`Closeable`,必须显式 close。

## 生命周期最小集

```java
// surfaceCreated 回调里
session = runtime.createSession(activity, surface, config, gameId);
session.startGame("game.js");        // game.js 在 session.getPaths().getCodeDir() 下

// Activity
@Override protected void onPause()  { if (session != null) session.pause();  }
@Override protected void onResume() { if (session != null) session.resume(); }
@Override protected void onDestroy(){
    if (session != null) { session.close(); session = null; }
}
```

`close()` 之后,带 `ensureNotDestroyed` 守卫的方法抛出 `MigoException`(code `-2000 ERR_SESSION_DESTROYED`,extends `RuntimeException`);`pause()`/`resume()` 安全 no-op,`dispatchTouchEvent` 返回 `false`。session 没 close 之前,native 内存、JS 上下文、平台通道都不会释放。

## Surface 三件套

对应 SurfaceHolder 三个回调:

```java
surfaceView.getHolder().addCallback(new SurfaceHolder.Callback() {
    public void surfaceCreated(SurfaceHolder h)  { /* createSession */ }
    public void surfaceChanged(SurfaceHolder h, int fmt, int w, int h) {
        session.updateSurface(h.getSurface(), w, h);
    }
    public void surfaceDestroyed(SurfaceHolder h) {
        session.onSurfaceDestroyed();       // 引擎推进 surface 丢失路径;JS 的 onHide 在这里停
    }
});
```

忘 `onSurfaceDestroyed` 是最常见的死锁来源:引擎不知道 surface 没了,GPU 资源还挂在被销毁的对象上。

## 触控与脚本通道

```java
surfaceView.setOnTouchListener((v, ev) -> session.dispatchTouchEvent(ev));

// 宿主 → JS
session.evaluateJavaScript("console.log('hello from host')");

// JS → 宿主:migo.sendToHost(type, payload) 走这里
session.setMessageHandler((type, payload) -> { /* JSON String,可能 null */ });
```

`evaluateJavaScript` 立即返回,脚本在 host 线程异步入队执行;想得到回执要用 `migo.sendToHost` 配合 MessageHandler。

### 桌面形态:鼠标、光标、指针锁定

在接了鼠标的设备上(扩展坞模式、Chromebook、桌面窗口化),把游戏所在的视图交给会话:

```java
session.setInputView(surfaceView);
```

会话接管该视图的 generic-motion 与 captured-pointer 监听:悬停、按键、滚轮进入内容的 `onMouseMove` / `onMouseDown` /
`onMouseUp` / `onWheel`(CSS 像素、DOM 按键序;Android 自己把鼠标点击变成的触摸照常进 `onTouch*`,与平台 PC 版一致),
`migo.setCursor()` 设置该视图的 `PointerIcon`,`requestPointerLock()` 用 pointer capture,捕获期间的相对位移累积成位置,
`movementX/Y` 照常可得。`MigoGameView` / `MigoGameActivity` 自动完成这些。自己的视图需要在
`View.onPointerCaptureChange` 里调用 `session.onPointerCaptureChanged(hasCapture)`;手动转发事件时用
`session.dispatchGenericMotionEvent(ev)`。窗口在自由窗口/分屏与最大化之间变化时(Android 11+),内容收到
`onWindowStateChange`;Android 应用不能自定窗口大小,`setWindowSize` 为 not supported。

### 物理键盘与手柄

同一个视图也接管 key 监听。接了键盘时,按键以 DOM `key` / `code` 进入 `onKeyDown` / `onKeyUp`(带修饰键与
`repeat`);返回、Home、音量、媒体等系统键仍归 Android。接了手柄时,手柄按标准布局(`mapping: "standard"`,4 轴、17 键)
出现在 `migo.getGamepads()` 里,上线/下线触发 `onGamepadConnected` / `onGamepadDisconnected`;摇杆过了设备死区才计数,
没有独立按键信号的模拟扳机行程超过 30/255 计为按下,方向帽映射成十字键;手柄的返回键不交给游戏,是玩家退出游戏的路。
Android 把按键与手柄运动发给**获得焦点**的视图:`GameSurfaceView` 自己可聚焦并在 `setInputView` 时取得焦点,自己的视图
要可聚焦并取得焦点;手动转发时用 `session.dispatchKeyEvent(ev)`。会话创建时已连接的手柄立即上线,关闭会话时全部下线。

## 状态广播:`OnStateChangeListener`

`setOnStateChangeListener(listener)` 拿引擎的 loading / running / error 状态跳变 — 用它驱动 loading UI,**不要**用 `SystemClock` 估算。`GameSessionListener`(另一接口)是更细的 loadingStart/loadingEnd 级钩子。

## 扫雷:四个跟 native 直接相关的方法

| 方法 | 语义 |
| --- | --- |
| `updateSurface(surface, w, h)` | surfaceChanged;w/h 是 **物理像素**(surface buffer 尺寸),直接把系统回调的原值传过来 |
| `onSurfaceDestroyed()` | 不销毁 session,只标记 surface 失效,JS onHide 路径对应 |
| `setDebugEnabled(boolean)` | 运行时切换 DebugOverlay |
| `getPaths()` | `GamePaths.getCodeDir()` 等;放置 game.js 的位置 |

## Handler setter(11 个域 + Listener)

以下开包前就装;详细合同见 [宿主能力总览](/docs/capabilities/overview/):

```java
session.setMessageHandler(...);      setAuthHandler(...);
session.setPermissionHandler(...);   setAdHandler(...);
session.setSettingHandler(...);      setShareHandler(...);
session.setNavigationHandler(...);   setPaymentHandler(...);
session.setSubpackageHandler(...);   setGameLogHandler(...);
session.setEcosystemHandler(...);
session.setListener(GameSessionListener);   // loading 级钩子
```

不设置 = 按总览表降级;装了之后不要中途换 handler — 正在进行的请求已经握着旧 handler 的 sink。

`EcosystemHandler` 是宿主自己的生态(好友与群、云存储、视频号、订阅消息、隐私协议……):请求按内容 API 名到达同一个
`call(request, sink)`,名字是契约 `ecosystem.names.calls` 的闭集。反方向两件事:`postEcosystemEvent(name, data[, reply])`
投递 `onVoIPChatStateChanged` 一类事件,带 `EcosystemReply` 的(`onCopyUrl` / `onHandoff` / `onNeedPrivacyAuthorization`)
收到内容的答复,最后一次 `done=true`,没人监听或运行时重启也会以 `null` 收尾;`setEcosystemValue(name, value)` 报告
`getExtConfigSync` / `isChatTool` 等同步 getter 的返回值,`null` 撤回。
