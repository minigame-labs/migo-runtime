The Bluetooth capability group covers three related but distinct layers:

- **Classic Bluetooth**: adapter lifecycle, device discovery, and pairing.
- **BLE (Bluetooth Low Energy)**: GATT connections, service/characteristic reads, writes and notifications, RSSI, and MTU negotiation.
- **Beacon (iBeacon)**: beacon scanning over BLE, independent of general device discovery.

Operation APIs are exposed under the `migo.*` namespace and answer by the common mini-game platform's rule: options carrying `success`, `fail` or `complete` are answered through those callbacks and the call returns nothing; options carrying none get a Promise. Event APIs use the `on*` / `off*` listener pattern described below.

Every operation answers **when it has happened** -- the connection made and its services discovered, the write acknowledged by the peripheral, the RSSI read from the device -- not when it was issued. A failure carries `errCode` (see Error codes below) beside `errMsg`.

## Adapter management

`openBluetoothAdapter` initializes the Bluetooth module and acquires exclusive adapter access. Android's device-discovery path requires the adapter to be open; Beacon and GATT operations perform their own availability and permission checks.

| API | Description | Main options fields |
| --- | --- | --- |
| `migo.openBluetoothAdapter` | Initializes the Bluetooth module and acquires exclusive adapter access | `mode` (default `'central'`) |
| `migo.closeBluetoothAdapter` | Releases the adapter, stops all discovery, and closes all GATT connections | — |
| `migo.getBluetoothAdapterState` | Returns `{ available, discovering }` | — |
| `migo.openSystemBluetoothSetting` | Opens the system Bluetooth settings page outside the game | — |

On Android, `openBluetoothAdapter` checks BLUETOOTH_CONNECT and acquires the adapter lock through `ExclusiveDeviceArbiter`. Only one session can hold the adapter at a time; if another game already holds it, the call fails with `fail in use by another game`.

```js
// Open the adapter → discover devices → close it
migo.openBluetoothAdapter({
  mode: 'central',
  success() {
    console.log('Bluetooth ready');
  },
  fail(err) {
    console.error('openBluetoothAdapter failed:', err);
  },
});
```

## Device discovery

| API | Description | Main options fields |
| --- | --- | --- |
| `migo.startBluetoothDevicesDiscovery` | Starts scanning for nearby devices until stopped | `services` (UUID filter array), `allowDuplicatesKey` (boolean, default `false`), `interval` (ms, default `0`), `powerLevel` (`'low'`/`'medium'`/`'high'`, default `'medium'`) |
| `migo.stopBluetoothDevicesDiscovery` | Stops scanning | — |
| `migo.getBluetoothDevices` | Returns all devices discovered by this session | — |
| `migo.getConnectedBluetoothDevices` | Returns the devices this game is connected to that offer one of the services (`{ devices: [{ name, deviceId }] }`) | `services` (required UUID array; empty returns all) |

Scanning continues until `stopBluetoothDevicesDiscovery`; nothing stops it silently, so stop once you have found what you need. New devices are delivered through `onBluetoothDeviceFound` (see Event subscriptions below). A device's `advertisData` is the advertisement's manufacturer-specific segment (company identifier first) and `serviceData` is keyed by service UUID, both as `ArrayBuffer`s; `localName`, `advertisServiceUUIDs` and `RSSI` come with them.

## BLE GATT services and characteristics

| API | Description | Main options fields |
| --- | --- | --- |
| `migo.getBLEDeviceServices` | Gets the device's GATT services | `deviceId` (required) |
| `migo.getBLEDeviceCharacteristics` | Gets the characteristics for a service | `deviceId` (required), `serviceId` (required) |
| `migo.readBLECharacteristicValue` | Reads a characteristic; the result is delivered through `onBLECharacteristicValueChange` | `deviceId`, `serviceId`, `characteristicId` (all required) |
| `migo.writeBLECharacteristicValue` | Writes a characteristic value, answering once the peripheral acknowledges it (`writeNoResponse` has no acknowledgement and answers when sent) | `deviceId`, `serviceId`, `characteristicId` (all required), `value` (`ArrayBuffer` / `ArrayBufferView`), `writeType` (`'write'` or `'writeNoResponse'`, default `'write'`) |
| `migo.notifyBLECharacteristicValueChange` | Subscribes or unsubscribes, answering once the peripheral accepts | `deviceId`, `serviceId`, `characteristicId`, `state` (all required), `type` (`'indication'` by default, or `'notification'`) |

The resolved value of `readBLECharacteristicValue` does not contain the characteristic data. The subsequent `onBLECharacteristicValueChange` event carries it in its `value` field as an `ArrayBuffer`.

## Event subscriptions

Register and remove every event listener with its matching `on*` / `off*` pair.

| Event pair | When it fires | Callback argument |
| --- | --- | --- |
| `migo.onBluetoothAdapterStateChange` / `migo.offBluetoothAdapterStateChange` | Adapter availability or discovery state changes | `{ available: boolean, discovering: boolean }` |
| `migo.onBluetoothDeviceFound` / `migo.offBluetoothDeviceFound` | A scan finds new devices (may fire more than once) | `{ devices: Device[] }` |
| `migo.onBLEConnectionStateChange` / `migo.offBLEConnectionStateChange` | BLE GATT connection state changes | `{ deviceId: string, connected: boolean }` |
| `migo.onBLECharacteristicValueChange` / `migo.offBLECharacteristicValueChange` | A characteristic read completes or a notification arrives | `{ deviceId, serviceId, characteristicId, value: ArrayBuffer }` |
| `migo.onBLEMTUChange` / `migo.offBLEMTUChange` | MTU negotiation completes | `{ deviceId: string, mtu: number }` |
| `migo.onBeaconUpdate` / `migo.offBeaconUpdate` | The Beacon list updates | `{ beacons: Beacon[] }` |
| `migo.onBeaconServiceChange` / `migo.offBeaconServiceChange` | Beacon service availability changes | `{ available: boolean, discovering: boolean }` |

```js
// Subscribe to characteristic notifications
function handleCharacteristicChange(event) {
  const { deviceId, serviceId, characteristicId, value } = event;
  const bytes = new Uint8Array(value);
  console.log('Characteristic value:', bytes);
}

migo.onBLECharacteristicValueChange(handleCharacteristicChange);

// Remove the listener when it is no longer needed
migo.offBLECharacteristicValueChange(handleCharacteristicChange);
```

## Android permissions and prerequisites

Android checks permissions when Bluetooth operations that require them are called, but **does not initiate runtime permission requests**. The host app must request and obtain the permissions at an appropriate time, normally before `openBluetoothAdapter`.

| Operation category | Android API < 31 | Android API ≥ 31 (Android 12+) |
| --- | --- | --- |
| Connection (adapter and GATT) | The policy requires no additional runtime connection permission | `android.permission.BLUETOOTH_CONNECT` |
| Scanning (discovery and Beacon) | `android.permission.ACCESS_FINE_LOCATION` | `android.permission.BLUETOOTH_SCAN` |

The permission checks come from `BluetoothPermissionPolicy.canConnect` and `BluetoothPermissionPolicy.canScan`.

When permission is missing, the relevant API fails and the error identifies the missing permission, for example:

```text
startBluetoothDevicesDiscovery:fail permission denied (BLUETOOTH_SCAN)
```

## Other platforms

Apple (iOS / macOS), Linux, Windows and OpenHarmony supply Bluetooth through the C ABI host-service channel: the host declares `MIGO_HOST_SERVICE_BLUETOOTH`, answers each request and posts events as the [Session reference](/docs/en/reference/session/) defines them, and delivers characteristic values with `migo_session_post_ble_characteristic_value`. On a host that does not declare it, operation APIs fail with `<apiName>:fail not supported` and event APIs only register listeners.

---

## Known caveats

- **Exclusive adapter access:** When multiple Migo games run on the same device, only the first session to open the adapter has access. A later `openBluetoothAdapter` call receives `fail in use by another game` until the first session calls `closeBluetoothAdapter`.
- **Asynchronous characteristic reads:** A successful `readBLECharacteristicValue` Promise only means that the command was submitted. The actual value arrives later through `onBLECharacteristicValueChange`.
