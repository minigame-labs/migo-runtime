The Apple platform ships as one SwiftPM package: every release has an asset
`migo-<version>-apple-sdk.zip` that unpacks to `MigoApple/`. It holds two products,
one per platform, with the same public surface: install a game package, then load it
into a `MigoGameView`.

| App | Product | `import` | Minimum OS | Content JavaScript runs in | Rendering |
| --- | --- | --- | --- | --- | --- |
| iOS | `MigoApplePerformancePlus` | `import MigoApplePerformancePlus` | iOS 15.2 | WebKit's WebContent process (JavaScriptCore with its JIT), in a Dedicated Worker | this app's process: Skia + ANGLE/Metal |
| macOS | `MigoMacV8` | `import MigoMacV8` | macOS 11 | this process: V8, with JIT and WebAssembly | this process: Skia + ANGLE/Metal |

## Why iOS is Performance+

iOS does not let a third-party process enable a JIT, but the WebContent process the
system spawns for WebKit has one: the boundary is drawn around the process, not the
engine. So Performance+ runs the game's JavaScript in WebContent -- the same
JavaScriptCore a WKWebView uses -- and keeps rendering in the app: each frame's
drawing commands cross the process boundary once, and Migo's renderer draws them into
the host's `CAMetalLayer`.

This means that on iOS **content JavaScript runs at the same speed as in a WKWebView**;
there is no "faster JS". The two differ in the path that gets a frame onto the screen.
Same-device, same-session comparisons are in
[migo-bench](https://github.com/minigame-labs/migo-bench).

A third lane, `MigoAppleWebKit` (a whole-page WebKit lane with no native renderer),
has a WebView session only and is **not in the SDK**: until `migo.*` is implemented
on the web platform itself, there is nothing for content to call there.

## 1. Get the SDK

Download `migo-<version>-apple-sdk.zip` and its `.attestation.json` from the
[SDK download page](https://minigame-labs.com/en/download.html) or
[GitHub Releases](https://github.com/minigame-labs/migo-runtime/releases), and check it
as described in [download verification](/docs/en/release/download-verification/)
before use. Unpack it, then in Xcode choose
*File → Add Package Dependencies → Add Local*, select `MigoApple/`, and link **one**
product from the table above to the app target.

## 2. Install and run a game

A game package is a directory with `game.js` at its root, shipped in the app. The
calls are identical on both platforms:

```swift
// .unsigned: the package is inside your own (already signed) app bundle.
// .verified(publicKey:): packages you download -- see "Content signing" below.
let configuration = try MigoGameView.Configuration.standard(contentSigning: .unsigned)
try MigoGameInstaller.install(
    package: Bundle.main.url(forResource: "my-game", withExtension: nil)!,
    id: "my-game", version: appBuildNumber, into: configuration.directories)

let gameView = MigoGameView(configuration: configuration)
gameView.onEvent = { event in
    // .ready / .exitRequested / .failed / .error / .gameLog; on iOS also .restarted / .console
}
view.addSubview(gameView)          // any size; the game gets it at first layout
gameView.loadGame(id: "my-game")   // entry defaults to game.js
```

`version` makes relaunches free: the same version is not copied again. When the game
asks to exit (`migo.exitMiniProgram()`) the view reports `.exitRequested`, and what
the app shows next is the app's; the same view can load the next game.

`MigoGameView` owns everything else: the engine session, the `CAMetalLayer`, the
display clock, touches (and on macOS the mouse, wheel and keys), the app lifecycle
and the soft keyboard. On iOS it also owns the audio session and recovery from a
WebContent crash: the game restarts from its entry, the view reports `.restarted`,
and saves on disk survive.

Complete iOS and macOS apps, resolving this asset and verifying its attestation, are
in [`apple-swift/` in migo-examples](https://github.com/minigame-labs/migo-examples/tree/master/apple-swift).
Every type, field and event is described item by item in the [Apple SDK reference](/docs/en/apple-sdk/game-view/).

## 3. Content signing

`contentSigning` has no default and must be chosen:

- `.unsigned`: only for packages shipped inside the signed app.
- `.verified(publicKey:)`: a 32-byte raw Ed25519 public key. Every package must then
  carry `manifest.json`
  (`{"version": 1, "entry": "game.js", "timestamp": <unix seconds>, "files": {"<path>": "<sha256 hex>", ...}}`)
  and `manifest.sig`, the raw 64-byte signature of `manifest.json`'s exact bytes. The
  engine verifies a package in full on its first launch and refuses one that does not
  match.

With signing enforced, the engine refuses a dynamically downloaded subpackage, since
it carries no signature; subpackages inside the package work.

## 4. Platform notes

### iOS

- The game's size is fixed when it starts (a mini-game lays itself out once), so lock
  the hosting view controller to the game's orientation -- and have it locked **before
  `MigoGameView`'s first layout**: an app whose Info.plist declares only the game's
  orientation, or a view controller that supports only that orientation presenting it. A
  root view controller that picks its orientation after launch lays out in the launch
  orientation first, and the game starts in a window of the wrong shape.
- `MigoGameView.unavailabilityReason` says whether the device can run the lane (for
  example below iOS 15.2); check it before offering the game.
- When the canvas is smaller than the screen -- common for games that size
  `canvas.width` in logical pixels -- the drawable takes the canvas's size and Core
  Animation scales it to the view, which is how a browser composites a canvas. The
  host does not set `CAMetalLayer.drawableSize` and leaves `contentsGravity` at its
  default, `.resize`.

### macOS

- Sign with the hardened runtime and `com.apple.security.cs.allow-jit`. Without it
  the view refuses to start and `onEvent` says why (V8 would die at its first compile,
  and a jitless V8 has no WebAssembly).
- Embed ANGLE with a Run Script build phase before signing, and add
  `@executable_path/../Frameworks` to the runpath search paths:

  ```bash
  bash "$MIGO_PACKAGE/Frameworks/Scripts/embed-apple-angle.sh" \
    --frameworks-dir "$MIGO_PACKAGE/Frameworks" \
    --destination "$TARGET_BUILD_DIR/$FRAMEWORKS_FOLDER_PATH" \
    --architectures "$ARCHS" \
    --sign "$EXPANDED_CODE_SIGN_IDENTITY"
  ```

- `Configuration.mouse` chooses how the mouse reaches content: `.touch` (phone-first
  content, the default), `.pointer` (PC-first content) or `.touchAndPointer` (only for
  content known to listen to exactly one of them).

## 5. Device capabilities

`MigoGameView` also answers what content asks of the device:

| API | iOS | macOS |
| --- | --- | --- |
| `setKeepScreenOn` | the idle timer; the app's own setting comes back when the game ends | a power assertion; likewise |
| `getNetworkType` / `onNetworkStatusChange` | `NWPathMonitor` (wired is `wifi`, cellular `unknown`, as on Android) | likewise |
| `vibrateShort` / `vibrateLong` | the Taptic Engine | answers "not supported" |
| `getBatteryInfo` | battery level and Low Power Mode | answers "not supported" |
| `getGameLogManager().log` | delivered to the app as `onEvent(.gameLog(json))` | likewise |

These are **refused rather than faked** on both lanes: `setDeviceOrientation` (the
size is fixed at start), `setEnableDebug` (there is no debug panel),
`getHeapStatistics` on iOS (content runs in WebKit's JavaScriptCore, which exposes no
heap figures), and downloaded subpackages when signing is enforced.

## 6. What has been verified

- **iOS devices**: on an iPhone XS Max (iOS 18.7), a game installed, loaded, turning
  frames on the display clock, exiting to the app and the next game running on the
  same layer; the soft keyboard; signed content verified, updated and refused when
  tampered; a game's packaged sounds playing through the host's audio. On the iPhone
  XS Max and an iPhone 15 Pro (iOS 26.6), the three benchmark games (PixiJS, Phaser,
  plain Canvas) and the measurement calibration pages all present at 60 fps.
- **iOS simulator** (every pull request): an acceptance suite running a real
  WebContent producer against a real renderer -- WebGL and 2D, textures, text,
  images, touches, a frame larger than one packet, synchronous readback and audio.
- **macOS** (every pull request): `MigoGameView` runs a game in an app signed with the
  hardened runtime and allow-jit -- V8's JIT and WebAssembly, Canvas2D on ANGLE,
  signed content verified and tampered content refused, and the view refusing to
  start without the entitlement.
- **Release**: `migo-<version>-apple-sdk.zip` is published only after the asset itself
  has been unpacked, built for iOS and macOS, and has run a game
  (`scripts/test-apple-sdk-release-asset.sh`).

## Building from source

This needs macOS and Xcode. Install the pinned ANGLE first (the build script never
downloads it), then build each platform group:

```bash
bash scripts/fetch-apple-angle.sh ios
bash scripts/fetch-apple-angle.sh ios-simulator
export MIGO_APPLE_BUILD_ROOT=/tmp/migo-apple-build
bash scripts/build-apple-sdk.sh --platform ios --configuration Release
bash scripts/build-apple-sdk.sh --platform ios-simulator --configuration Release
```

The macOS V8 group, building ANGLE from source and the embedding details are in
[`platforms/apple/README.md`](https://github.com/minigame-labs/migo-runtime/blob/HEAD/platforms/apple/README.md).
