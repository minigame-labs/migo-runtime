蓝牙能力组涵盖三个相对独立的功能层：

- **经典蓝牙（Classic BT）**：适配器生命周期、设备扫描、配对。
- **BLE（低功耗蓝牙）**：GATT 连接、服务/特征读写与通知、RSSI、MTU 协商。
- **Beacon（iBeacon）**：基于 BLE 的信标扫描，独立于通用设备发现之外。

操作 API 均挂载在 `migo.*` 命名空间下，按通用小游戏平台的规则作答：`options` 里带 `success` / `fail` / `complete` 时通过回调作答、调用本身无返回值；都不带时返回 Promise。事件 API 使用下文的 `on*` / `off*` 监听器方式。

每个操作在**真正完成时**才作答——连接建立且服务已发现、写入被外设确认、RSSI 从设备读到——而不是在命令下发时。失败的结果带 `errCode`（见下文错误码），与 `errMsg` 并列。

## 适配器管理

`openBluetoothAdapter` 可初始化蓝牙模块并获取适配器独占权。Android 的设备发现路径要求适配器已打开；Beacon 与 GATT 操作会各自执行可用性和权限检查。

| API | 说明 | 主要 options 字段 |
| --- | --- | --- |
| `migo.openBluetoothAdapter` | 初始化蓝牙模块，获取适配器独占权 | `mode`（默认 `'central'`） |
| `migo.closeBluetoothAdapter` | 释放适配器，停止所有扫描，断开全部 GATT 连接 | — |
| `migo.getBluetoothAdapterState` | 返回 `{ available, discovering }` | — |
| `migo.openSystemBluetoothSetting` | 打开系统蓝牙设置页面（跳出游戏） | — |

`openBluetoothAdapter` 在 Android 侧会检查 BLUETOOTH_CONNECT 权限并通过 `ExclusiveDeviceArbiter` 申请适配器独占锁。同一时刻只有一个 session 能持有适配器——若另一个游戏已持有，将收到 `fail in use by another game` 错误。

```js
// 打开适配器 → 发现设备 → 关闭
migo.openBluetoothAdapter({
  mode: 'central',
  success() {
    console.log('Bluetooth ready');
  },
  fail(err) {
    console.error('openBluetoothAdapter failed:', err);
  },
});
```

## 设备发现

| API | 说明 | 主要 options 字段 |
| --- | --- | --- |
| `migo.startBluetoothDevicesDiscovery` | 开始扫描附近设备，直到调用 stop | `services`（过滤 UUID 数组）、`allowDuplicatesKey`（bool，默认 `false`）、`interval`（ms，默认 `0`）、`powerLevel`（`'low'`/`'medium'`/`'high'`，默认 `'medium'`） |
| `migo.stopBluetoothDevicesDiscovery` | 停止扫描 | — |
| `migo.getBluetoothDevices` | 返回本次 session 中扫描到的全部设备 | — |
| `migo.getConnectedBluetoothDevices` | 返回本游戏已连接、且提供指定服务的设备（`{ devices: [{ name, deviceId }] }`） | `services`（必填，UUID 数组；空数组返回全部） |

扫描持续到 `stopBluetoothDevicesDiscovery`，不会被静默停止；找到目标后应主动停止以省电。发现到新设备时通过 `onBluetoothDeviceFound` 事件推送（见下文事件订阅）。设备对象的 `advertisData` 是广播里的厂商自定义数据段（公司 ID 在前），`serviceData` 以服务 UUID 为键，二者都是 `ArrayBuffer`；另有 `localName`、`advertisServiceUUIDs`、`RSSI`。

## BLE GATT 服务与特征

| API | 说明 | 主要 options 字段 |
| --- | --- | --- |
| `migo.getBLEDeviceServices` | 获取设备的 GATT 服务列表 | `deviceId`（必填） |
| `migo.getBLEDeviceCharacteristics` | 获取指定服务的特征列表 | `deviceId`（必填）、`serviceId`（必填） |
| `migo.readBLECharacteristicValue` | 读取特征值，结果通过 `onBLECharacteristicValueChange` 事件推送 | `deviceId`、`serviceId`、`characteristicId`（均必填） |
| `migo.writeBLECharacteristicValue` | 写入特征值，外设确认后作答（`writeNoResponse` 无确认，发出即答） | `deviceId`、`serviceId`、`characteristicId`（均必填）、`value`（`ArrayBuffer` / `ArrayBufferView`）、`writeType`（`'write'` 或 `'writeNoResponse'`，默认 `'write'`） |
| `migo.notifyBLECharacteristicValueChange` | 订阅或取消订阅特征通知，外设接受后作答 | `deviceId`、`serviceId`、`characteristicId`、`state`（均必填）、`type`（`'indication'` 默认 / `'notification'`） |

`readBLECharacteristicValue` 的结果不在 Promise resolved 值中，而由后续 `onBLECharacteristicValueChange` 事件携带（`value` 字段为 `ArrayBuffer`）。

## 事件订阅

所有事件均通过对称的 `on*` / `off*` 方法注册和移除监听器。

| 事件对 | 触发时机 | 回调参数 |
| --- | --- | --- |
| `migo.onBluetoothAdapterStateChange` / `migo.offBluetoothAdapterStateChange` | 蓝牙适配器可用性或发现状态改变 | `{ available: bool, discovering: bool }` |
| `migo.onBluetoothDeviceFound` / `migo.offBluetoothDeviceFound` | 扫描发现新设备（可能多次触发） | `{ devices: Device[] }` |
| `migo.onBLEConnectionStateChange` / `migo.offBLEConnectionStateChange` | BLE GATT 连接状态变化 | `{ deviceId: string, connected: bool }` |
| `migo.onBLECharacteristicValueChange` / `migo.offBLECharacteristicValueChange` | 特征值读取完成或通知到达 | `{ deviceId, serviceId, characteristicId, value: ArrayBuffer }` |
| `migo.onBLEMTUChange` / `migo.offBLEMTUChange` | MTU 协商完成 | `{ deviceId: string, mtu: number }` |
| `migo.onBeaconUpdate` / `migo.offBeaconUpdate` | Beacon 列表更新 | `{ beacons: Beacon[] }` |
| `migo.onBeaconServiceChange` / `migo.offBeaconServiceChange` | Beacon 服务可用性变化 | `{ available: bool, discovering: bool }` |

```js
// 订阅 BLE 特征通知
function handleCharacteristicChange(event) {
  const { deviceId, serviceId, characteristicId, value } = event;
  const bytes = new Uint8Array(value);
  console.log('Characteristic value:', bytes);
}

migo.onBLECharacteristicValueChange(handleCharacteristicChange);

// 不再需要时移除
migo.offBLECharacteristicValueChange(handleCharacteristicChange);
```

## Android 权限与前提

Android 会在需要权限的 Bluetooth 操作调用时检查权限，但**不主动发起运行时权限申请**——宿主 App 必须在合适的时机（通常在 `openBluetoothAdapter` 之前）先完成权限请求。

| 操作类别 | Android API < 31 所需权限 | Android API ≥ 31（Android 12+）所需权限 |
| --- | --- | --- |
| 连接（adapter、GATT） | 该策略不要求额外的运行时连接权限 | `android.permission.BLUETOOTH_CONNECT` |
| 扫描（discovery、Beacon） | `android.permission.ACCESS_FINE_LOCATION` | `android.permission.BLUETOOTH_SCAN` |

权限检查逻辑来源：`BluetoothPermissionPolicy.canConnect` 与 `BluetoothPermissionPolicy.canScan`。

权限不满足时，相应 API 会失败并在错误消息中标注缺少的权限名，例如：

```text
startBluetoothDevicesDiscovery:fail permission denied (BLUETOOTH_SCAN)
```

## 其他平台

Apple（iOS / macOS）、Linux、Windows、OpenHarmony 经 C ABI 宿主服务通道提供蓝牙：宿主声明 `MIGO_HOST_SERVICE_BLUETOOTH`，按 [Session 参考](/docs/reference/session/) 的约定应答每个请求、投递事件，并用 `migo_session_post_ble_characteristic_value` 投递特征值。未声明的宿主上，操作 API 以 `<apiName>:fail not supported` 失败，事件 API 只注册监听器、不会有事件。

## 已知注意事项

- **适配器独占**：同一设备上同时运行多个使用 migo 的游戏时，只有首个打开适配器的 session 持有访问权；后续调用 `openBluetoothAdapter` 会收到 `fail in use by another game`，直至前一个 session 调用 `closeBluetoothAdapter`。
- **特征值读取**：`readBLECharacteristicValue` 成功表示读请求已下发，值通过随后的 `onBLECharacteristicValueChange` 事件到达。
