# Frozen MP3 presentation references

These are original synthetic music/tone inputs, not third-party recordings.
`music.mp3` and `music.i16le` now live in the product `decoder/mp3/fixtures`
folder as the single authoritative copies. The MP3 has 480137 original stereo frames at 48000 Hz, generated by the
existing `audio-whole-file-performance.py::cases` recipe. The source WAV SHA is
recorded in `sources.json`; encoding used libmp3lame at 128 kb/s with Xing.

The i16le outputs were frozen from unmodified, checksum-pinned minimp3-sys
0.6.0 / minimp3_ex before helper extraction. The complete nonzero music PCM
matches the formerly decoded raw PCM's valid segment exactly; its frame count
also matches the independent input signal. The acceptance gate verifies every
frozen file SHA and never regenerates these references. The CBR/VBR encoded
inputs remain in the existing product `decoder/mp3/fixtures` folder; their
frozen i16 references here represent 6912 stereo / 5184 mono frames without Xing.

The Rust contracts compare every sample, not a prefix/hash only, and retain
three generated free-format layouts (417, 2303, and padded 2304 before TAG).
They check the upstream full reader separately after shared-helper extraction,
actual native codec entry counts, native heap calls and retirement, declared
length/caps and malformed Xing optional fields. Native allocations are counted
only in the instrumented test build. A separate `--plain` release run checks
the native ABI and PCM with those hooks absent. These primitive tests do not claim product cursor or executor cancellation,
platform builds or performance acceptance. The separate product gate checks
the real cursor/job integration with the same native source.
